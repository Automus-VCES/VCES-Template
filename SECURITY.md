# Security Policy

## Scope

This repository publishes engineering guidance and workflow examples. Issues may affect this repository, its automation, or adopters copying examples.

## Reporting

Do not publish credentials, exploit details, or sensitive vulnerability information in a public issue. Use GitHub private vulnerability reporting only if it is enabled for this repository. If it is unavailable, contact the repository maintainers through a verified private channel; do not post sensitive details publicly while waiting for a channel to be provided.

**Maintainer setup:** Confirm whether private vulnerability reporting is enabled in repository Settings → Security → Private vulnerability reporting. If it is not enabled, configure it or publish a monitored private security contact before inviting external vulnerability reports. No private reporting channel is asserted by this document.

Include affected paths, impact, safe reproduction details, and suggested mitigation. Do not include real secrets or personal data.

## Response

Maintainers should acknowledge, assess, prioritize, coordinate remediation, and communicate resolution responsibly.

## Safe use of templates

Adopters MUST review workflow permissions, third-party actions, secrets exposure, dependency sources, and deployment targets before enabling copied workflows. Examples are starting points, not security certification.

## Supported versions

Security fixes are prioritized for the latest published VCES version. Earlier copies should be updated or independently assessed.
