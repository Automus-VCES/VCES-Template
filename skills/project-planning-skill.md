# Project Planning Skill

## Purpose
Turn a requested app or feature into the smallest clear, testable plan.

## When to use
Use for a new app, a material feature, unclear requirements, or a change with meaningful user, data, security, or operational impact. Skip formal planning for routine, low-risk edits.

## Workflow
1. Clarify the user problem, intended users, and desired outcome.
2. Define scope, explicit non-goals, and the smallest useful first release.
3. Identify critical user journeys, data handled, external dependencies, and trust boundaries.
4. Write acceptance criteria that can be observed or tested.
5. Note only material risks, assumptions, dependencies, and approval points.
6. Choose Basic, Standard, or Production controls based on impact and exposure.

## Verification
- Scope and non-goals are unambiguous.
- Each important requirement has an observable acceptance criterion.
- High-impact risks and approval needs are identified.
- The plan is proportionate; routine work is not burdened with unnecessary documents.

## Avoid
Do not invent requirements, design for hypothetical scale, create lengthy specifications for small tasks, or treat every idea as a commitment.
