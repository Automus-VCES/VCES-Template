# Contributing

> Customize this document for the project's actual collaboration model. For solo or informal projects, keep only the useful guidance; a mandatory branch/PR workflow may not be needed.

Contributions should follow the adopted VCES version and project requirements where defined.

## Workflow
1. Confirm objective, scope, and acceptance criteria.
2. Use the project's branch/review convention if applicable.
3. Implement a focused change.
4. Add/update tests and docs when needed.
5. Run relevant validation commands.
6. Inspect the diff.
7. Use PR review where the project benefits from collaboration or review.
8. Address relevant feedback before release.

## Optional review checklist
- [ ] Scope and acceptance criteria are clear.
- [ ] Relevant tests and checks ran.
- [ ] Security and data impacts considered.
- [ ] Documentation is current where needed.
- [ ] No secrets, local state, or unrelated files included.
- [ ] Migration and rollback implications considered.
- [ ] Review and CI requirements, if configured, are satisfied.

Use the commit convention in project instructions if one is defined. Do not bypass required review or CI. Do not force-push shared branches without authorization.
